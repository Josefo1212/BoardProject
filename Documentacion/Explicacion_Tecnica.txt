PIZARRA COLABORATIVA EN TIEMPO REAL
DOCUMENTACION TECNICA DEL BACKEND
==================================================

1. VISION GENERAL
--------------------------------------------------
El backend es un servidor WebSocket escrito en Node.js (ES Modules) que
mantiene el estado central de una pizarra colaborativa. Los clientes se
conectan por WiFi, envían operaciones de dibujo y reciben en tiempo real
las operaciones de los demás.

Tecnologías:
- Node.js >= 20.
- Paquete ws para el servidor WebSocket.
- Paquete js-yaml para leer la configuración.
- Persistencia en un archivo JSON local.
- Pruebas con node:test.

El backend NO sirve archivos HTTP del frontend. Solo expone WebSocket.
El cliente estático debe servirse aparte (por ejemplo, con Python,
Vite, nginx o cualquier servidor HTTP).


2. ARQUITECTURA
--------------------------------------------------
2.1 Componentes

Cliente A ─┐
Cliente B ─┼── WebSocket ── Servidor Node.js ── Memoria (#strokes)
Cliente C ─┘                         │
                                     └── Archivo data/board.json

Servidor:
- Acepta conexiones WebSocket.
- Valida identidad mínima (origen e IP opcional).
- Valida cada mensaje recibido.
- Mantiene la pizarra en memoria.
- Difunde cambios a los demás clientes.
- Controla límites, ritmo, latidos y errores.
- Guarda y restaura la pizarra.

Cliente:
- Dibuja localmente.
- Envía operaciones al servidor.
- Aplica las operaciones recibidas de otros clientes.

2.2 Flujo de datos

CLIENTE A                         SERVIDOR                         CLIENTE B
   |                                 |                                 |
   |-- stroke-start ---------------->|                                 |
   |                                 |-- stroke-start ---------------->|
   |-- stroke-points --------------->|                                 |
   |                                 |-- stroke-points --------------->|
   |-- stroke-end ------------------>|                                 |
   |                                 |-- stroke-end ------------------>|
   |                                 |                                 |
   |-- clear ----------------------->|                                 |
   |                                 |-- clear ----------------------->|

El emisor no recibe eco de sus propios mensajes porque ya dibujó
localmente. El servidor usa #broadcast(message, senderSocket) excluyendo
el socket emisor.

4. CONFIGURACION
--------------------------------------------------
4.1 Archivo config.yaml

server:
  host: "0.0.0.0"
  port: 3005
  maxClients: 50
  pingIntervalMs: 30000
  maxPayloadBytes: 262144
  maxBufferedBytes: 8388608

access:
  mode: "open"
  allowedOrigins:
    - "*"
  allowedIps:
    - "192.168.100.21"

limits:
  maxStrokes: 5000
  maxPointsPerStroke: 10000
  maxTotalPoints: 2000000
  maxMessagesPerSecond: 500

persistence:
  enabled: true
  file: "data/board.json"
  debounceMs: 500

4.2 Módulo config.js

export function loadConfig(configPath, rootDir)

Responsabilidades:
1. Leer el YAML con fs.readFileSync y yaml.load.
2. Validar que la raíz sea un objeto.
3. Aplicar defaults de DEFAULTS.
4. Validar tipos y rangos.
5. Resolver la ruta del archivo de persistencia.

Helpers internos:
- isPlainObject(value): comprueba objeto no nulo y no array.
- readString(value, fallback, name): valida texto no vacío.
- readNumber(value, fallback, name, { min, max, integer }): valida
  números, enteros y rangos.
- readStringList(value, fallback, name): valida listas de textos y
  descarta elementos vacíos.

Reglas relevantes:
- access.mode debe ser "open" o "allowlist".
- Si no se indica access.mode y existen IPs en el formato antiguo
  clients[].ip, el modo por defecto es "allowlist".
- allowedIps siempre incluye 127.0.0.1 y ::1.
- allowedOrigins vacío cae al default ["*"].
- persistence.file relativo se resuelve contra la raíz Server/.
- persistence.enabled usa Boolean(...) sobre el valor recibido.

Resultado:
{
  server: { host, port, maxClients, pingIntervalMs,
            maxPayloadBytes, maxBufferedBytes },
  access: { mode, allowedOrigins, allowedIps },
  limits: { maxStrokes, maxPointsPerStroke, maxTotalPoints,
            maxMessagesPerSecond },
  persistence: { enabled, file, debounceMs }
}


5. ARRANQUE Y APAGADO
--------------------------------------------------
Archivo: src/index.js

Secuencia de arranque:
1. Calcula rootDir a partir de import.meta.url.
2. loadConfig(Server/config.yaml, rootDir).
3. new Communication(config).
4. Registra los eventos "listening" y "error" del servidor.
5. Si el puerto está ocupado, se muestra el error del WebSocket.

Evento "listening":
- Imprime la URL ws://host:port.
- Imprime el modo de acceso y la ruta de persistencia.

Apagado ordenado:
- process.on("SIGINT")  -> shutdown("SIGINT")
- process.on("SIGTERM") -> shutdown("SIGTERM")
- process.on("uncaughtException") -> shutdown("uncaughtException")
- process.on("unhandledRejection") -> shutdown("unhandledRejection")

shutdown(signal):
1. Evita ejecuciones duplicadas con la bandera shuttingDown.
2. await communication.close().
3. Ajusta process.exitCode a 0 o 1.

Communication.close():
1. Marca #closed = true.
2. Limpia el intervalo de heartbeat.
3. Cancela el temporizador de persistencia pendiente.
4. Fuerza el guardado final con #flushPersistence().
5. Envía { type: "server-shutdown" } a cada cliente.
6. Cierra cada socket con código 1001 ("Servidor apagado").
7. Limpia #clients.
8. Cierra el WebSocketServer con un límite de espera de 3 segundos.


6. CLASE COMMUNICATION
--------------------------------------------------
Archivo: src/communication.js
Clase exportada: Communication.

6.1 Campos privados principales

#server              Instancia de WebSocketServer.
#clients             Set de clientes conectados.
#strokes             Map strokeId -> trazo.
#totalPoints         Total de puntos en memoria.
#allowedIps          Set de IPs permitidas.
#allowedOrigins      Set de orígenes permitidos.
#allowlistEnabled    true si access.mode === "allowlist".
#maxClients          Máximo de conexiones simultáneas.
#maxPayloadBytes     Tamaño máximo de mensaje WebSocket.
#maxBufferedBytes    Umbral de backpressure por socket.
#maxStrokes          Máximo de trazos.
#maxPointsPerStroke  Máximo de puntos por trazo.
#maxTotalPoints      Máximo total de puntos.
#maxMessagesPerSecond Límite de mensajes por cliente por segundo.
#persistence         Configuración de persistencia.
#persistTimer        Temporizador de guardado con debounce.
#persistChain        Cola de promesas para escrituras serializadas.
#heartbeatTimer      Intervalo de ping/pong.
#closed              Bandera de cierre.

El Map #strokes conserva el orden de inserción. Por eso la instantánea
mantiene el orden en que se crearon los trazos.

6.2 Constructor

new Communication({ server, access, limits, persistence })

Pasos:
1. Guarda la configuración en campos privados.
2. Normaliza las IPs permitidas con #normalizeIp.
3. Crea el Set de orígenes permitidos.
4. Carga la pizarra persistida con #loadPersistedBoard.
5. Crea WebSocketServer con:
   - host y port,
   - maxPayload,
   - clientTracking: false (el servidor gestiona su propio Set),
   - perMessageDeflate: false (menor latencia).
6. Registra el evento "connection".
7. Si pingIntervalMs > 0, crea el intervalo de heartbeat.
8. Usa timer.unref() para que el proceso no quede retenido por timers.

Getters públicos:
- server: devuelve el WebSocketServer.
- clientCount: número de clientes conectados.
- strokeCount: número de trazos en memoria.

6.3 Ciclo de vida de una conexión

#handleConnection(socket, request):

1. Registra un listener de error del socket.
2. Comprueba el origen HTTP:
   - Sin Origin (clientes no navegador): permitido.
   - Con Origin: debe estar en #allowedOrigins o existir "*".
   - Si falla: error ORIGIN_NOT_ALLOWED y cierre 1008.
3. Normaliza remoteAddress.
4. Si el modo es allowlist y la IP no está permitida:
   error UNAUTHORIZED_CLIENT y cierre 1008.
5. Si #clients.size >= #maxClients:
   error SERVER_FULL y cierre 1013.
6. Crea el objeto cliente:
   {
     id: crypto.randomUUID(),
     socket,
     isAlive: true,
     messageWindowStart,
     messageCount,
     rateLimited,
     errorWindowStart,
     errorCount,
     strokeIds: Set
   }
7. Agrega el cliente a #clients.
8. Registra "pong", "message" y "close".
9. Envía el mensaje snapshot:
   {
     type: "snapshot",
     clientId,
     clients,
     strokes: [...]
   }
10. Difunde presence con el nuevo conteo de clientes.

#handleDisconnect(client):
- Elimina el cliente del Set.
- Si el servidor no está cerrando, difunde presence con el nuevo conteo.

6.4 Pipeline de mensajes

#handleMessage(client, rawMessage, isBinary):

1. Si #closed, ignora el mensaje.
2. Si isBinary, responde INVALID_MESSAGE.
3. #allowMessage(client): aplica rate limiting.
4. JSON.parse(rawMessage.toString("utf8")):
   - Si falla, responde INVALID_MESSAGE.
5. #applyMessage(client, message).
6. Si el resultado tiene reply, lo envía solo al emisor.
7. Si el resultado tiene broadcast, lo difunde a los demás.
8. Si el resultado tiene persist, llama a #schedulePersist.
9. Cualquier excepción se convierte en error tipado:
   - ProtocolError conserva su code.
   - Otros errores usan INVALID_MESSAGE.

6.5 Enrutamiento

#applyMessage(client, message):
- Valida que message sea objeto.
- switch por message.type:
  "stroke-start"  -> #applyStrokeStart
  "stroke-points" -> #applyStrokePoints
  "stroke-end"    -> #applyStrokeEnd
  "stroke"        -> #applyStroke
  "clear"         -> #applyClear
  "ping"          -> responde { type: "pong", timestamp }
  default         -> UNSUPPORTED_MESSAGE

Cada handler devuelve:
{
  broadcast?: mensaje para difundir,
  reply?: mensaje solo para el emisor,
  persist?: boolean
}

6.6 Handlers de pizarra

#applyStrokeStart(client, message):
- Valida strokeId con #validateStrokeId.
- Valida style con #validateStyle.
- Busca si existe el trazo.
- Si existe y es de otro cliente: STROKE_CONFLICT.
- Si es nuevo y #strokes.size >= #maxStrokes: BOARD_FULL.
- Valida point opcional con #validatePoint.
- Controla #maxTotalPoints.
- Si el trazo ya existe y es del mismo cliente, lo reinicia.
- Si no existe, crea:
  { strokeId, points, style, authorId, complete: false }
- Incrementa #totalPoints.
- Agrega el id a client.strokeIds.
- Difunde stroke-start con strokeId, style, authorId y, si existe,
  point.
- No persiste todavía.

#applyStrokePoints(client, message):
- #requireOwnedStroke valida que el trazo exista y sea del cliente.
- #validatePoints valida el lote.
- #ensurePointCapacity valida límites por trazo y totales.
- Agrega los puntos al trazo.
- Difunde stroke-points con strokeId, points y authorId.
- No persiste todavía.

#applyStrokeEnd(client, message):
- #requireOwnedStroke.
- Si llegan points finales no vacíos, los valida y los agrega.
- Si el trazo quedó sin puntos, lo elimina y marca discard.
- Si tiene puntos, marca complete = true.
- Difunde stroke-end con strokeId, authorId y, si corresponde,
  points o discard.
- Persiste.

#applyStroke(client, message):
- Implementa el formato completo/compatible.
- Valida strokeId, points y style.
- Respeta propiedad del trazo y límites.
- Reemplaza o crea el trazo completo y lo marca complete = true.
- Difunde stroke con todos los puntos y el estilo.
- Persiste.

#applyClear(client):
- Limpia #strokes.
- Reinicia #totalPoints.
- Limpia client.strokeIds de todos los clientes.
- Difunde { type: "clear", authorId }.
- Persiste.

6.7 Validación

#requireOwnedStroke(client, rawStrokeId):
- Valida el id.
- Si no existe: STROKE_NOT_FOUND.
- Si authorId no coincide: STROKE_CONFLICT.

#ensurePointCapacity(stroke, pointsToAdd):
- stroke.points.length + pointsToAdd <= #maxPointsPerStroke.
- #totalPoints + pointsToAdd <= #maxTotalPoints.

#validateStrokeId(value):
- Debe ser string.
- Se recorta con trim.
- Debe cumplir /^[A-Za-z0-9_-]{1,128}$/.

#validatePoints(value):
- Debe ser array no vacío.
- No puede superar #maxPointsPerStroke.
- Valida cada punto.

#validatePoint(value):
- Debe ser objeto.
- x e y deben ser números finitos entre 0 y 1.
- pressure es opcional; si existe, número finito entre 0 y 1.
- Devuelve solo x, y y pressure para no guardar campos arbitrarios.

#validateStyle(value):
- undefined o null -> {}.
- Debe ser objeto no array.
- color: string no vacío, máximo 32 caracteres.
- width: número entre 0.5 y 100.
- opacity: número entre 0 y 1.
- Devuelve solo las propiedades permitidas.

Todas las coordenadas se guardan normalizadas (0 a 1), no en píxeles.
Eso permite que cada cliente las escale a su propio tamaño de canvas.

6.8 Rate limiting y errores

#allowMessage(client):
- Ventana de 1 segundo por cliente.
- Al iniciar una ventana nueva reinicia messageCount y rateLimited.
- Si messageCount > #maxMessagesPerSecond:
  - Envía RATE_LIMITED una sola vez por ventana.
  - Devuelve false y descarta el mensaje.

#reportError(client, code, message):
- Ventana de 10 segundos por cliente.
- Envía { type: "error", code, message }.
- Si supera 30 errores en la ventana, cierra con código 1008.

6.9 Broadcast, envío y backpressure

#broadcast(message, senderSocket = null):
- Serializa una sola vez con JSON.stringify.
- Recorre #clients.
- Omite al emisor si senderSocket coincide.
- Omite sockets que no estén OPEN.
- Si socket.bufferedAmount > #maxBufferedBytes, omite al cliente lento.
- Envía dentro de try/catch.
- Devuelve la cantidad de destinatarios y avisa si hubo descartes.

#sendJson(socket, message):
- Solo envía si el socket está OPEN.
- Serializa y envía dentro de try/catch.
- Devuelve true/false según el resultado.

#reject(socket, code, message, closeCode):
- Envía un mensaje de error.
- Cierra el socket con el código indicado y un texto corto.

6.10 Heartbeat

#checkHeartbeat():
- Se ejecuta cada pingIntervalMs.
- Si client.isAlive es false, termina el socket con terminate().
- Si está vivo, lo marca false y envía un ping WebSocket.
- El evento "pong" vuelve a marcar isAlive = true.
- Si ping() lanza error, termina el socket.

Esto detecta laptops que se desconectaron sin cerrar correctamente.

6.11 Instantánea

#snapshotStrokes():
Devuelve un array con:
{
  strokeId,
  points,
  style,
  authorId,
  complete
}

Incluye trazos parciales (complete false) para que un cliente que entra
mientras alguien está dibujando vea también lo que está en curso.

6.12 Persistencia

Carga: #loadPersistedBoard()
- Solo si persistence.enabled.
- Lee el archivo con fs.readFileSync.
- Si no existe (ENOENT), no muestra error.
- Parsea JSON y recorre data.strokes.
- Valida cada trazo con las mismas funciones de validación.
- Restaura authorId o usa "persisted".
- Respeta #maxStrokes y #maxTotalPoints.
- Ignora trazos inválidos sin romper el arranque.

Guardado: #schedulePersist()
- Solo si está habilitada, el servidor no está cerrado y no hay un
  temporizador pendiente.
- Crea un setTimeout con debounceMs.
- Al dispararse, llama a #flushPersistence.

#flushPersistence():
- Toma solo trazos con complete === true.
- Construye:
  {
    version: 1,
    savedAt: ISO,
    strokes: [{ strokeId, points, style, authorId }]
  }
- Crea el directorio con fs.promises.mkdir({ recursive: true }).
- Escribe en archivo temporal board.json.tmp.
- Renombra a board.json para evitar archivos incompletos.
- Serializa escrituras con #persistChain = #persistChain.then(...).
- close() espera la cadena para guardar antes de apagar.

Importante:
- Los trazos en curso no se guardan.
- Un trazo vacío se elimina y no se guarda.
- Al hacer clear se guarda el archivo sin trazos.

6.13 Origen e IP

#isOriginAllowed(origin):
- true si no hay Origin.
- true si existe "*".
- true si el Origin está en el Set.
- false en otro caso.

#normalizeIp(ip):
- Quita el prefijo IPv4 mapeado en IPv6 ("::ffff:").
- Quita corchetes de IPv6.
- Devuelve "" si no es string.


7. PROTOCOLO WEBSOCKET
--------------------------------------------------
Todos los mensajes son texto JSON. Los mensajes binarios se rechazan.

7.1 Cliente -> Servidor

Iniciar trazo:
{
  "type": "stroke-start",
  "strokeId": "uuid-o-id-unico",
  "point": { "x": 0.1, "y": 0.2 },
  "style": { "color": "#172033", "width": 3, "opacity": 1 }
}

Agregar puntos:
{
  "type": "stroke-points",
  "strokeId": "uuid-o-id-unico",
  "points": [
    { "x": 0.11, "y": 0.22 },
    { "x": 0.12, "y": 0.23 }
  ]
}

Terminar trazo (points finales es opcional):
{
  "type": "stroke-end",
  "strokeId": "uuid-o-id-unico",
  "points": [{ "x": 0.13, "y": 0.24 }]
}

Trazo completo (formato compatible/legacy):
{
  "type": "stroke",
  "strokeId": "uuid-o-id-unico",
  "points": [
    { "x": 0.1, "y": 0.2 },
    { "x": 0.2, "y": 0.3 }
  ],
  "style": { "color": "#172033", "width": 3 }
}

Borrar pizarra:
{
  "type": "clear"
}

Ping de aplicación:
{
  "type": "ping"
}

7.2 Servidor -> Cliente

Snapshot al conectar:
{
  "type": "snapshot",
  "clientId": "uuid-del-cliente",
  "clients": 3,
  "strokes": [
    {
      "strokeId": "uuid-trazo",
      "points": [{ "x": 0.1, "y": 0.2 }],
      "style": { "color": "#172033", "width": 3 },
      "authorId": "uuid-autor",
      "complete": true
    }
  ]
}

Presencia:
{
  "type": "presence",
  "clients": 3
}

Reenvíos:
- stroke-start
- stroke-points
- stroke-end
- stroke
- clear

Cada reenvío de trazo incluye authorId del emisor.

Pong:
{
  "type": "pong",
  "timestamp": 1730000000000
}

Apagado del servidor:
{
  "type": "server-shutdown",
  "message": "El servidor se está apagando."
}

Error:
{
  "type": "error",
  "code": "INVALID_POINT",
  "message": "Las coordenadas deben estar entre 0 y 1."
}

7.3 Códigos de error

INVALID_MESSAGE       JSON inválido, mensaje no objeto o binario.
UNSUPPORTED_MESSAGE   Tipo de mensaje desconocido.
INVALID_STROKE        strokeId inválido o lista de puntos inválida.
INVALID_POINT         Coordenadas o presión fuera de rango.
INVALID_STYLE         Color, grosor u opacidad inválidos.
STROKE_NOT_FOUND      Se intentó modificar un trazo inexistente.
STROKE_CONFLICT       El trazo pertenece a otro cliente.
STROKE_TOO_LARGE      Se superó el máximo de puntos por trazo.
BOARD_FULL            Se superó el máximo de trazos o de puntos totales.
RATE_LIMITED          Demasiados mensajes por segundo.
UNAUTHORIZED_CLIENT   IP no permitida en modo allowlist.
ORIGIN_NOT_ALLOWED    Origen HTTP no permitido.
SERVER_FULL           Máximo de clientes alcanzado.

7.4 Códigos de cierre WebSocket

1001  Servidor apagándose.
1008  Cliente no autorizado, origen no permitido, demasiados errores.
1013  Servidor lleno.


8. REGLAS Y LIMITES
--------------------------------------------------
- Un mensaje no puede superar maxPayloadBytes (256 KB por defecto).
- Un trazo no puede superar maxPointsPerStroke (10000 por defecto).
- La pizarra no puede superar maxStrokes (5000 por defecto).
- La pizarra no puede superar maxTotalPoints (2 000 000 por defecto).
- Cada cliente no puede superar maxMessagesPerSecond (500 por defecto).
- Máximo de clientes: maxClients (50 en config.yaml).
- Solo el autor puede modificar su trazo.
- Las coordenadas deben estar entre 0 y 1.
- El estilo se filtra a color, width y opacity.
- Los clientes lentos se omiten temporalmente por backpressure.
- Los clientes que no responden al ping se terminan.


9. PRUEBAS
--------------------------------------------------
Archivo: test/communication.test.js
Ejecución: pnpm test
Runner: node --test

Cobertura actual (6 pruebas):

1. Difunde trazos completos y limpia la pizarra.
   - Dos clientes conectados.
   - Snapshot inicial vacío.
   - Envío de stroke completo.
   - Recepción por el otro cliente con authorId correcto.
   - Envío de clear y recepción.

2. Transmite trazos en vivo y los incluye en la instantánea.
   - stroke-start, stroke-points y stroke-end.
   - Verificación de puntos.
   - Un tercer cliente recibe el trazo completo en el snapshot.
   - Verificación de complete = true.

3. Rechaza coordenadas inválidas sin modificar la pizarra.
   - Coordenada x = 2.
   - Respuesta INVALID_POINT.
   - strokeCount sigue en 0.

4. Responde ping con pong.
   - Verifica timestamp numérico.

5. Bloquea clientes fuera de la lista en modo allowlist.
   - Respuesta UNAUTHORIZED_CLIENT.

6. Persiste la pizarra entre reinicios.
   - Guarda en un archivo temporal.
   - Reinicia Communication con el mismo archivo.
   - Verifica que el trazo reaparezca en el snapshot.

Las pruebas usan puerto 0 para obtener un puerto libre y no chocar con
el servidor real.


10. INTEGRACION CON EL CLIENTE
--------------------------------------------------
El cliente actual usa Client/app.js como punto de entrada. Sus módulos
JavaScript se distribuyen en Client/js/: configuración, estado, referencias
del DOM, utilidades, lienzo y comunicación. Los estilos se distribuyen en
Client/styles/, mientras que Client/style.css funciona como punto de entrada:
- Dibuja localmente.
- Envía un mensaje stroke completo al soltar el puntero.
- Envía clear al pulsar Limpiar.
- Al recibir snapshot redibuja todos los trazos.
- Al recibir stroke dibuja el trazo remoto.
- Al recibir clear limpia el canvas.

El frontend envia:
1. Dibuja el trazo localmente mientras se mueve el puntero.
2. Envia un mensaje `stroke` completo al soltar.

Enviar cada trazo completo evita que una interrupcion durante los mensajes
fragmentados deje la conexion en un estado inconsistente. La pizarra local
continua actualizandose en tiempo real y el servidor distribuye cada trazo
terminado a los demas clientes.

También conviene que el frontend:
- Use crypto.randomUUID() para strokeId.
- Mantenga trazos locales y remotos separados al redibujar.
- Escale las coordenadas normalizadas al tamaño actual del canvas.
- Maneje snapshot, presence, error y server-shutdown.
- Implemente reconexión con reintento.

La URL del WebSocket se define en codigo usando el host actual y el
puerto 3005; la vista no muestra ningun campo para editarla.

El servidor ya soporta ambos formatos: el streaming y el stroke completo.

12. POSIBLES MEJORAS
--------------------------------------------------
- Servir el frontend desde el mismo servidor para un solo comando.
- Salas o pizarras múltiples mediante rutas o query string.
- Autenticación con token y nombres de usuario.
- Deshacer/rehacer por cliente o colaborativo.
- Compresión selectiva de snapshots grandes.
- Persistencia en base de datos en lugar de JSON local.
- TLS para usar wss:// en redes no confiables.
- Métricas y logs estructurados.
- Limpieza de trazos parciales de clientes desconectados.
- Pruebas de carga con muchas conexiones simultáneas.


13. RESUMEN
--------------------------------------------------
El backend mantiene una única pizarra en memoria protegida por
validaciones y límites. Cada operación se valida, se aplica al estado
central y se difunde a los demás clientes. La conexión se mantiene viva
con ping/pong, los clientes lentos o inválidos se controlan, y la
pizarra se guarda de forma atómica para sobrevivir a reinicios. El
cliente puede usar el protocolo de streaming para lograr colaboración
punto por punto en tiempo real.
